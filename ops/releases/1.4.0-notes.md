# HardGuard25 1.4.0 release notes

Minor release. The alphabet and checksum algorithm are unchanged. The only runtime behavior change is invalid-input error message text.

## Security
- Invalid-input errors name the first offending code point (`U+XXXX`) and never echo the caller's input, in JavaScript, Python and Go. Shared `rejection_messages` vectors enforce this across runtimes.
- Hashed meta Content Security Policy on the landing page and generator, with CI checks for the hashes and for inline handlers.
- `/.well-known/security.txt`, an expanded `SECURITY.md`, weekly Scorecard and deployed-surface audits, and workflow hardening.

## Documentation
- Exact Mod-25 check digit detection profile, pinned in shared vectors. Payloads of 24 characters or fewer are recommended when the check digit is enabled.
- Generation length is documented as trusted configuration with no library maximum.

## Upgrade note
Code or tests that match on the old invalid-input error text must be updated to match on the code point form.

Full detail is in `CHANGELOG.md`. Publication evidence will be recorded in `ops/releases/1.4.0.json` after release.
